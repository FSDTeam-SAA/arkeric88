# Step 1: Destination suggestions (Velari intake)

This document is the contract for `POST /get_suggested_city` and
`POST /regenerate_suggested_city`. Step 2 (`POST /get_tour_plan`) and the full
flow are in `BACKEND_INTEGRATION_GUIDE.md`.

## 1. What changed

The questionnaire is now the 11-step **Velari emotional travel intake**
(`formId: velari_emotional_travel_intake`, version 1). The form definition is
checked in at `app/schemas/velari_intake_form.json`, and tests make sure the
API accepts exactly its option codes.

Suggestions now come from the destination catalog in `data/`:

| File | Role |
|---|---|
| `1. AI_IMPORT_DESTINATIONS.csv` | 72 candidate destinations. The only source of suggestions. |
| `2. DISCOVERY_BACKLOG.csv` | 928 geographic records. Never suggested to guests. |
| `3. IMPORT_RULES.csv` | Required behavior, implemented in `src/core/destination_matching.py`. |
| `4. INTAKE_MAPPING.csv` | Role of each intake answer, implemented in `src/core/intake_mappings.py`. |

The old 15-question payload, the retreat workbook matcher and
`POST /v2/retreat-recommendations` have been removed. Old payloads now return `422`.

Matching is deterministic, with no LLM involved:

1. **Hard exclusions come before ranking.** A destination is excluded when:
   - the catalog flags a conflict with a must-avoid restriction;
   - suitability for a high-impact must-avoid restriction (mobility/accessibility) is unknown;
   - it is certainly beyond the guest's travel distance;
   - it has a verified nightly price above budget.
2. **Scoring** (out of 100):

   | Component | Points |
   |---|---|
   | Desired feelings (`trip_goals`) | 40 |
   | Chosen moments | 25 |
   | Setting | 15 |
   | Pace | 10 |
   | Travel distance fit | 10 |

   Each prefer-avoid restriction the catalog flags costs 8 points and adds an explained tradeoff.
3. **Selection:** 2–3 options, from different countries and with varied settings.

Nothing is relaxed silently. If no destination survives, the response says
which answer blocks a match.

## 2. Request

Field names are the form's `key` values. Send option **codes**, not labels.

```json
{
  "recent_feelings": ["stretched_thin"],
  "recent_feelings_other": null,
  "trip_goals": ["restoration", "reflection"],
  "trip_prompt": "need_a_break",
  "trip_prompt_other": null,
  "preferred_moments": ["quiet_privacy", "spa_wellness", "nature_wildlife"],
  "preferred_environments": ["coast", "mountains"],
  "trip_pace": "one_highlight",
  "travel_party": "couple",
  "party_adults": 2,
  "party_children": 0,
  "party_rooms": 1,
  "activity_restrictions": ["no_long_drives", "avoid_extreme_heat"],
  "restriction_severity_no_long_drives": "prefer_avoid",
  "restriction_severity_avoid_extreme_heat": "must_avoid",
  "restriction_notes": null,
  "departure_location": "Lisbon",
  "travel_distance": "manageable_flight",
  "travel_timing": "exact_dates",
  "check_in_date": "2026-12-12",
  "check_out_date": "2026-12-17",
  "trip_nights": 5,
  "budget_per_night": 400
}
```

Validation rules (all return `422` with field-level messages):

| Field | Rule |
|---|---|
| `recent_feelings`, `trip_goals`, `preferred_environments` | 1–2 unique codes |
| `preferred_moments` | 1–3 unique codes |
| `preferred_environments` | `surprise_me` must be the only choice |
| `recent_feelings_other` / `trip_prompt_other` | Required when `something_else` is chosen; dropped otherwise |
| Party fields | `solo` is fixed at 1 adult / 0 children / 1 room. Omitted counts use the form defaults. `party_rooms` cannot exceed the number of travelers. |
| `restriction_severity_<option>` | Required for every selected restriction (`must_avoid` or `prefer_avoid`). May also be sent as one object: `"restriction_severity": {"no_long_drives": "prefer_avoid"}`. |
| Exact dates | Both dates required, check-out after check-in, check-in not in the past. `trip_nights` may be omitted (it is derived) but must match the dates if sent. |
| `travel_period` | Required when `travel_timing` is `month_season` |
| `trip_nights` | 1–90, required |
| `budget_per_night` | USD per room, per night, 100–7000. `7000` means "$7,000+" (open-ended). |
| Unknown fields | Rejected |

Optional fields not on the form yet (send them when available):

- `party_child_ages`: one age (0–17) per child. Live room rates need these.
- `departure_latitude`, `departure_longitude`, `departure_country`: from a
  places-autocomplete widget. Without them the backend geocodes `departure_location`.

What to show the guest:

- **Show `match_reasons`, `tradeoffs` and `unresolved_facts`.** Don't hide
  tradeoffs or unresolved facts behind a collapsed area.
- **Treat every suggestion as a candidate, not a confirmed recommendation.**
  `verification` says what is still unchecked. No price or availability is
  claimed, and `budget_status` is `UNKNOWN` until live rates exist.
- **Use `guest_context` to reflect the guest's own answers back** (labels only).
  `trip_goals[].definition` is the short theme definition to display.
- **Ask `clarifications` as optional follow-ups.** Examples: child ages,
  more than 2 adults in one room, an "Other" must-avoid with no notes, or a
  dietary need with no notes.

### No valid result

When nothing survives the hard exclusions, the call still returns `200`, with
`match_status: "no_valid_result"`, an empty `suggested_cities`, and:

```json
"no_valid_result": {
  "blocking_constraints": [
    {"constraint": "unverified_high_impact:mobility_accessibility",
     "field": "restriction_severity_mobility_accessibility",
     "excluded_count": 67,
     "explanation": "'Mobility or accessibility' is marked as something you must plan around, and 67 destinations have no verified information about it yet. We won't treat unknown as suitable."}
  ],
  "question": "Could you tell us more about what you need ...?",
  "relaxed_automatically": false
}
```

Show the explanation and question, then send the guest's change through
`/regenerate_suggested_city` with `intake_updates`.

> **Note:** a **must-avoid** "Mobility or accessibility" always produces this
> result today. No catalog row has verified accessibility information, and the
> rules say unknown high-impact suitability is not a pass. "Prefer to avoid"
> returns options, with accessibility listed as unresolved.

## 4. Regenerate: `POST /regenerate_suggested_city`

```json
{ "session_id": "...", "user_instruction": "optional note", "intake_updates": { } }
```

- **Without `intake_updates`:** the same answers are re-ranked, and destinations
  already shown in this session are excluded. When none are left, the call
  returns `404` and suggests sending `intake_updates`.
- **With `intake_updates`:** you can change any intake fields, for example
  `{"restriction_severity_mobility_accessibility": "prefer_avoid"}` or
  `{"travel_distance": "anywhere"}`.
  - The merged answers are re-validated (`422` if invalid; the session is
    left unchanged) and ranked from scratch.
  - Changing `travel_party` without sending new counts resets the counts to that party's defaults.

The response has the same shape as §3.

## 5. Privacy

`recent_feelings_other` and `trip_prompt_other` may hold private emotional
text. They are:

- stored in the session and returned only by `GET /session/{session_id}`;
- never used for matching;
- never put in LLM prompts or map/travel API queries;
- never echoed in suggestion responses.

The departure geocode receives only `departure_location`.
