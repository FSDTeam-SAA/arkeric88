# 9. Catalogue 1,000 and Matching Changes (Phase 1)

Changes to the AI service for Phase 1 of the October 2026 request: the 1,000-destination
catalogue, departure-location fallbacks, and destination matching. Intake mapping and scoring
versions are now `2026-10-29.1`.

## What the backend and frontend need to know

| Change | API effect | Action needed |
| --- | --- | --- |
| Catalogue v3: 1,000 destinations | `total_candidate_count` is 1000. `catalog_version` adds `release`, `editorial_count` (72), `location_enriched_count` (928), `without_coordinates_count` (28). | None. |
| Never two cards from one country | `suggested_cities` may hold **1–3** cards. A `data_gaps` note explains when fewer than 3. | Accept 1 or 2 cards. Keep the duplicate-country check as a safety net; it should no longer trigger. |
| "Decide later" for departure | `departure_location` is optional. Omitted or blank = decide later. `travel_distance` is then optional (defaults to `anywhere`). | Send no `departure_location` when the guest skips. A non-blocking clarification asks for it later. |
| Unmatched departure text is accepted | A city or airport Google can't match no longer blocks anything. `origin.status` is `UNVERIFIED` with `input_text` (what the guest typed). | Don't re-ask the question on `UNVERIFIED`; show suggestions. |
| Original and matched departure kept apart | `origin.input_text` (guest's words) and `origin.normalized_name` (Google's match). New status `NOT_PROVIDED`. | Store both if needed. |
| Strongest desired outcome | New optional `primary_trip_goal` (must be one of `trip_goals`). It gets 60% of the 40 outcome points. | Optional "Which matters most?" when two goals are chosen (see `velari_intake_form.json`). |
| Evidence tier per card | `verification.evidence_tier`: `editorial` or `location_enriched`. `candidate_status` can be `LOCATION_ENRICHED`. | Use for admin views; don't show to guests. |
| Mobility + Must avoid | No longer returns zero results. Destinations whose catalogue text flags mobility are excluded; unknown ones rank lower and say accessibility still has to be checked. | None. |

## Matching changes

- **All 1,000 rows are ranked.** The 928 location-enriched rows score 10 points lower, as
  IMPORT_RULES.csv "Destination matching confidence" requires ("rank lower until enriched").
- **Template text is ignored.** Clauses repeated on 100+ rows (for example "Confirm on-the-ground
  experiences, guest accessibility, suitable dates and any required transfers.") are left out of
  restriction checks, keyword matching and card text. Before this, that one sentence made "No long
  drives" exclude 946 of 1,000 destinations.
- **Staff wording removed from card text.** "Consider when guest seeks …" and "This is an editorial
  interpretation, not a guest-specific conclusion." no longer reach guests.
- **New theme and pace values.** `Inspirer` → Inspiration. `Explorer` → Discovery, plus half credit
  for Adventure (IMPORT_RULES.csv "Discovery/Adventure"). Paces such as `Gentle|Balanced` match either.
- **Ties no longer go to the alphabetically first ID.** Equal scores are ordered by a hash of the
  guest's answers. Same answers → same results; different answers → different tie order.
- **Country names are compared canonically.** "United States" and "United States of America" are one
  country.
- **Unmatched departure with a named country.** For "Austin, TX, USA", Nearby is limited to the
  same world region (North America) without claiming a distance.
- **Duplicate IDs in a catalogue update** keep the first row and log a warning; no ID is replaced.

## Not changed yet

- Budget still can't filter destinations: no catalogue row has a verified price. It applies once
  live hotel rates exist (Booking.com / LiteAPI).
- Booking.com is not integrated in this service; hotel rates use LiteAPI when enabled.
- Seasonality, travel effort and itinerary logistics are unchanged (Phase 2).
